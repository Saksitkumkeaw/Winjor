คุณกำลังทำงานในโปรเจกต์ **Winjor Cinema** ที่ `C:\Users\acer\Winjor` (Next.js + TypeScript + Tailwind + shadcn/ui + Supabase) เป้าหมายคือเพิ่ม **ระบบสนับสนุนการตัดสินใจ (DSS)** เพื่อส่งงานวิชา DSS **พรุ่งนี้** ให้ทำงานครบ, demo ได้จริง, และเตรียมเนื้อหาสไลด์

### บรีฟจากอาจารย์

- นำเสนอสไลด์ + Demo โปรแกรม

### ข้อตัดสินใจที่ทำไว้แล้ว (ห้ามเปลี่ยนโดยไม่ถามผู้ใช้)
- **หัวข้อหลัก:** DSS วางแผนสั่งซื้อวัตถุดิบ ใช้ตัวแบบสินค้าคงคลังจากบทที่ 7 ของวิชา (EOQ, ROP, Safety Stock, Quantity Discount)
- **ไม่ใช้ ML:** ใช้ค่าเฉลี่ย (d) และส่วนเบี่ยงเบนมาตรฐาน (σ) ของยอดใช้ย้อนหลังจริง ใส่สูตร
- **ความแม่นยำ:** วัดด้วย **Backtest** (Service Level ที่ได้จริงเทียบเป้า, วันที่ของขาด, ต้นทุน) และ MAPE ของการใช้ค่าเฉลี่ยในอดีตประมาณอนาคต
- **ส่วนเสริม:** ส่วน "ควรเพิ่มรอบหนังเรื่องไหน" บนหน้าจัดรอบฉาย (Data-Driven DSS)
- **หน้าภาพรวมหลังบ้าน:** เพิ่มแถบ "ต้องตัดสินใจ" + ข้อมูลวันนี้ + กราฟเล็ก
- **ข้อมูล demo:** สร้างข้อมูลจำลองย้อนหลัง 90 วัน ใส่ลงฐานข้อมูล โดยลบออกได้ทั้งชุด
- **ภาษา UI:** ไทยทั้งหมด ตามแบบหน้าเดิม

### เฟส 2: โมเดล (TypeScript ล้วน + unit test)

**`lib/dss/inventory.ts`** (pure functions)
- `mean`, `stdDev` (sample) ของยอดใช้รายวัน
- `zForServiceLevel`: 90% → 1.282, 95% → 1.645, 99% → 2.326 (ตามตาราง ไม่ต้องคำนวณ inverse normal)
- `eoq(F, D, H)` = √(2FD/H) โดย H = C × I และ D กับ H ต้องใช้หน่วยเวลาเดียวกัน (รายปี: D = d × 365)
- `safetyStock(z, σ, L)` = z × σ × √L **(√L ห้ามคูณ L ตรง ๆ)**
- `reorderPoint(d, L, SS)` = d × L + SS (วัดจากของในมือ)
- `annualCost` = DC + (Q/2)H + F(D/Q) + SS×H และแยกส่วน DC กับส่วนที่เกี่ยวข้องให้เห็นชัด
- `quantityDiscountOption`: EOQ ที่ราคาลด ถ้าต่ำกว่าขั้นต่ำให้ใช้ขั้นต่ำ แล้วเทียบต้นทุนรวมเต็ม (ตามบท 7.9)
- `buildOptions`: สร้างทางเลือก
  - **A วิธีเดิม:** สั่งเมื่อ ≤ `reorder_level` ครั้งละ 7 วันของยอดใช้เฉลี่ย (บันทึกเป็นสมมติฐาน)
  - **B EOQ + ROP + SS**
  - **C ส่วนลด** (ถ้ามี)
  - คืนค่าต้นทุน/ปี, โอกาสไม่ขาดต่อรอบ (ของ A คิดจาก Φ((reorder_level − dL)/(σ√L))), จำนวนวันที่พอใช้ และทางเลือกที่ต้นทุนต่ำสุด
- `explain`: สร้างข้อความเหตุผลภาษาไทย เช่น "แนะนำสั่ง … เพราะเหลือ … ต่ำกว่าจุดสั่งซื้อ … (ใช้ … ต่อวัน × รอ … วัน + สำรอง …)"
- รับ `demandAdjustPct` (ช่องวิจารณญาณของผู้ใช้) ไปคูณทั้ง d และ σ

**`lib/dss/backtest.ts`**
- แบ่งข้อมูล: 60 วันแรกใช้หา d และ σ ส่วน 30 วันหลังใช้ทดสอบ
- จำลองรายวัน: ใช้ยอดจริงของแต่ละวัน เมื่อ inventory position ≤ ROP ให้สั่ง Q แล้วของมาถึงหลัง L วัน ถ้ายอดใช้มากกว่าของที่มี ถือว่าของขาด
- ผลลัพธ์ของแต่ละนโยบาย (A, B, C):
  - Cycle Service Level จริง = รอบสั่งที่ไม่ขาด ÷ รอบสั่งทั้งหมด
  - จำนวนวันที่ของขาด
  - ค่าสั่งซื้อ + ค่าเก็บรักษาในช่วงทดสอบ
- MAPE ของการใช้ค่าเฉลี่ยช่วงเทรนเทียบยอดจริงรายวันในช่วงทดสอบ

**Unit test** (`lib/dss/inventory.test.ts`, `lib/dss/backtest.test.ts`) ต้องผ่านตัวอย่างจากชีทวิชา:
- หลอดภาพ: D = 10,000, C = 400, I = 0.05, F = 360 → Q* = 600, ค่าสั่ง = ค่าเก็บ = 6,000, ต้นทุนเกี่ยวข้อง 12,000
- รายวัน: d = 100, F = 500, H = 0.40 → Q* = 500, t0 = 5 วัน
- Safety stock: d = 100, σ = 10, L = 4, z = 1.645 → SS ≈ 32.9, ROP ≈ 432.9
- ส่วนลด (แบตเตอรี่): D = 1,200, F = 200, I = 25%, ราคา 300 / 270 (≥100) / 264 (≥400) → เลือก Q = 100 ที่ 270 ได้ TC = 329,775 ส่วน Q = 400 ได้ 330,600
- Backtest: ข้อมูลคงที่ไม่มีความผันผวน ต้องไม่เกิดของขาด

### เฟส 3: หน้า DSS หลัก

เพิ่มเมนู **"วางแผนสั่งซื้อ"** ต่อจาก "สต็อก" ใน `NAV_ITEMS` และเพิ่มลิงก์จากแถบเตือนในหน้า `/admin/stock`

**`/admin/stock/planning`** (ภาพรวม)
- ตัวเลือกด้านบน: ข้อมูลย้อนหลัง 30/60/90 วัน และระดับบริการ 90/95/99% (เก็บใน search params)
- การ์ดสรุป: ต้องสั่งวันนี้ X รายการ, ใกล้ถึงจุดสั่ง X รายการ, Service Level จาก backtest เทียบเป้า
- ตาราง: วัตถุดิบ, คงเหลือ, d, σ, พอใช้อีกกี่วัน, ROP, Q*, สถานะ
  - สถานะมี 3 ระดับ: 🔴 สั่งเลย (คงเหลือ ≤ ROP), 🟡 ใกล้ถึงจุดสั่ง (≤ ROP + d×2), 🟢 ปกติ
  - คลิกแถวเพื่อเข้าหน้ารายละเอียด

**`/admin/stock/planning/[id]`** (หน้าตัดสินใจ) เรียงตาม 4 ขั้นของ Simon:
1. **Intelligence:** การ์ดคงเหลือ, d, σ, พอใช้อีกกี่วัน และกราฟยอดใช้รายวันที่มีเส้นค่าเฉลี่ย
2. **Design:**
   - แถบ What-if (client component คำนวณทันทีด้วยฟังก์ชันจาก `lib/dss/inventory.ts`): % ปรับคาดการณ์ (−30 ถึง +60), ระดับบริการ, L, F
   - การ์ดทางเลือก A/B/C พร้อมต้นทุน/ปี และโอกาสไม่ขาด ตัวที่ต้นทุนต่ำสุดมีกรอบเน้น
   - กล่องแสดงสูตรพร้อมแทนค่าจริง (Q*, SS, ROP)
3. **Choice:** กล่องคำแนะนำพร้อมเหตุผล ถ้าแนะนำ C ต้องบอกเงื่อนไขเรื่องพื้นที่เก็บ ปุ่ม "อนุมัติทางเลือกที่แนะนำ", "เลือกทางเลือกอื่น", "แก้จำนวนแล้วอนุมัติ" ใช้ server action ใน `lib/dss/actions.ts` บันทึกลง `reorder_decisions` (การรับของเข้าคลังยังใช้ฟอร์มเดิมในหน้าสต็อก)
4. **Implementation / Feedback:** ผล backtest (Service Level จริง/เป้า, วันที่ของขาด A เทียบ B, ต้นทุนเปลี่ยนกี่ %, MAPE) และตารางประวัติการตัดสินใจ

เพิ่มช่องกรอก C, F, I, L และส่วนลด ใน `components/admin/ingredient-form.tsx` พร้อม validation ใน `lib/admin/validation.ts` และ test

### เฟส 4: ส่วนเสริม

**ส่วน "ควรเพิ่มรอบหนังเรื่องไหน"** ด้านบน `/admin/showtimes`
- ตัวเลือกย้อนหลัง 7/14/30 วัน
- **กราฟ 4 ช่อง:** แกนนอน = รอบเฉลี่ยต่อวัน, แกนตั้ง = อัตราเข้าชม, ขนาดวงกลม = ตั๋ว เส้นเกณฑ์ 75% และ 30% เส้นแบ่งแนวตั้ง = ค่ากลางของรอบต่อวัน
  - มุมบนซ้าย = เพิ่มรอบ, บนขวา = รักษาไว้, ล่างขวา = ลดรอบ, ล่างซ้าย = เฝ้าดู
- แท่งอัตราเข้าชมรายเรื่อง มีเส้น 75% และสัดส่วนรอบที่ขายหมด
- รายการคำแนะนำพร้อมเหตุผลและแนวโน้มเทียบช่วงก่อน ปุ่ม "สร้างรอบ" เลื่อนไปที่ฟอร์มสร้างรอบเดิมพร้อมเลือกหนังไว้ให้ถ้าทำได้
- ใช้ SVG หรือ div ล้วน ไม่ต้องเพิ่มไลบรารีกราฟ

**หน้าภาพรวม `/admin`**
1. **แถว "ต้องตัดสินใจ" (บนสุด):** วัตถุดิบที่ต้องสั่งวันนี้, หนังที่ควรเพิ่มรอบ, หนังที่ควรลดรอบ พร้อมชื่อและลิงก์
2. **แถว "วันนี้":** ยอดขาย (เทียบเมื่อวาน), ตั๋ว (ออนไลน์/หน้าร้าน), อัตราเข้าชมรอบวันนี้ + รอบที่ขายหมด, ออเดอร์รอรับสินค้า
3. **ช่องเดิม 3 ช่อง:** คงไว้ แต่ลดน้ำหนักการแสดงผล
4. **กราฟเล็ก:** ยอดขาย 7 วัน และอัตราเข้าชมรายเรื่อง 7 วัน
